## Overview

Discovery commands help you find, index, and manage skills in your FastSkill ecosystem. These commands provide semantic search, vector indexing, and repository management capabilities.

<Callout type="info">
**Command Architecture**:
- **Repository Management**: Use `fastskill repo` for all repository operations (add, remove, list, info, update, test, refresh) and catalog browsing (skills, show, versions)
- **Skill Discovery**: Use `fastskill skill search` (remote catalogs by default; add `--local` for installed skills and embeddings)
</Callout>

<Callout>
For detailed documentation on specific commands, see the dedicated command pages linked below.
</Callout>

## Command Reference

### fastskill skill search

Query skills. **Default scope is remote** (catalog APIs). Use `--local` to search installed skills; local embedding search uses OpenAI when configured and respects `--embedding`.

<Callout type="info">
See [`skill search`](/cli-reference/search-command) for complete output documentation.
</Callout>

```bash
# Remote catalog search (default)
fastskill skill search "text processing"

# Installed skills + embeddings / keyword (see --embedding)
fastskill skill search "analyze data" --local

# Remote, limit and JSON
fastskill skill search "convert files" --limit 5 --json

# Remote, single repository
fastskill skill search "process text" --repository my-repo
```

**What it does (local scope)**:
- Optionally embeds the query and searches the local vector index when `--embedding` is not `false`
- Uses the skills directory from `skill-project.toml` / discovery unless `--skills-dir` is set

**Options**:
- `<QUERY>`: Search string
- `--local`: Search installed skills only
- `--remote`: Explicit remote search (same as default when `--repository` is not used alone)
- `--repository <NAME>`: Limit remote search to one configured repository
- `-l, --limit <N>`: Max results (default: 10)
- `-f, --format <FORMAT>`: `table`, `json`, `grid`, or `xml` (default: table)
- `--json`: Shorthand for `--format json`
- `--embedding <true|false|auto>`: **Local only**; ignored for remote search
- `--skills-dir <PATH>`: Override skills directory (local search / service bootstrap)

**Output**:
- **table** (default): Human-readable rows
- **json** / **xml** / **grid**: Structured or machine-readable layouts

### fastskill index rebuild

Rebuild the vector search index by scanning all installed skills. Updates embeddings and similarity database.

<Callout type="info">
See [`index rebuild`](/cli-reference/reindex-command) for complete documentation.
</Callout>

```bash
# Reindex all skills (uses configured skills directory)
fastskill index rebuild

# Force reindex (ignore file hash cache)
fastskill index rebuild --force

# Optional explicit skills directory
fastskill index rebuild --skills-dir ./.claude/skills
```

**What it does**:
- Scans the configured skills directory for installed skills
- Generates embeddings for SKILL.md content when embedding search is enabled
- Stores vectors in the local index database used by `fastskill skill search --local`
- Tracks file hashes (SHA256) for change detection
- Skips unchanged files unless `--force` is set

**Options**:
- `--skills-dir <PATH>`: Override skills directory for this run
- `--force`: Rebuild all embeddings (ignore hash cache)
- `--max-concurrent <N>`: Accepted for compatibility but currently a **no-op** — reindex embeds skills sequentially (default value: 5)
- `--progress` / `--no-progress`: Control progress UI
- `-v, --verbose`: Show per-skill processing details

**When to use**:
- After installing new skills
- After updating existing skills
- When search results are stale or incomplete
- When skill content has changed

### fastskill repo

Manage skill repositories for discovering and installing skills. Supports multiple repository types with authentication and priority-based resolution. This is the **primary command** for repository management and catalog browsing.

<Callout type="info">
See [`repo` commands](/cli-reference/repository-command) for complete documentation with actions
and authentication.
</Callout>

```bash
# List all configured repositories
fastskill repo list

# Add new repository
fastskill repo add team-tools --repo-type git-marketplace https://github.com/team/skills.git

# Remove repository
fastskill repo remove team-tools

# Show repository details
fastskill repo info team-tools

# Update repository configuration
fastskill repo update team-tools --priority 1

# Test repository connectivity
fastskill repo test team-tools

# Refresh repository cache
fastskill repo refresh
```

**What it does**:
- Manages repository configuration in `skill-project.toml` [tool.fastskill.repositories]
- Supports multiple repository types: `git-marketplace`, `http-registry`, `zip-url`, `local`
- Handles authentication: PAT, SSH key, SSH, Basic Auth, API Key
- Implements priority-based conflict resolution (lower priority = higher precedence)

**Repository Types**:

**Git Marketplace**:
```toml
[[tool.fastskill.repositories]]
name = "team-skills"
type = "git-marketplace"
url = "https://github.com/team/skills.git"
priority = 0
branch = "main"
# Optional authentication — the token is read from the named environment variable,
# never stored inline in the file.
auth = { type = "pat", env_var = "GITHUB_TOKEN" }
```

**HTTP Registry**:
```toml
[[tool.fastskill.repositories]]
name = "public-registry"
type = "http-registry"
index_url = "https://registry.fastskill.dev/index"
priority = 0
# Optional authentication — the key is read from the named environment variable.
auth = { type = "api_key", env_var = "FASTSKILL_API_KEY" }
```

**ZIP URL**:
```toml
[[tool.fastskill.repositories]]
name = "skill-archive"
type = "zip-url"
base_url = "https://example.com/skills"
priority = 0
```

**Local**:
```toml
[[tool.fastskill.repositories]]
name = "local-skills"
type = "local"
path = "./local-skills"
priority = 0
```

**Authentication Types** (the `type` value in the `auth` table):
- `pat`: Personal Access Token (for git repositories) — `{ type = "pat", env_var = "..." }`
- `ssh-key`: SSH key path — `{ type = "ssh-key", path = "..." }`
- `ssh`: SSH connection — `{ type = "ssh", key_path = "..." }`
- `basic`: Basic authentication — `{ type = "basic", username = "...", password_env = "..." }`
- `api_key`: API key (for HTTP registries) — `{ type = "api_key", env_var = "..." }`

**Priority Resolution**:
When skills are available in multiple repositories, priority determines the order:
- Lower priority numbers are checked first
- Default priority: 0
- Higher priority values are checked later

## Search and Reindex Workflow

### Initial Setup

```bash
# 1. Install skills
fastskill project install

# 2. Reindex for search
fastskill index rebuild

# 3. Test search
fastskill skill search "text processing"
```

### After Updates

```bash
# 1. Update skills
fastskill skill update

# 2. Reindex to refresh embeddings
fastskill index rebuild --force

# 3. Verify search results
fastskill skill search "new feature"
```

### Adding New Skills

```bash
# 1. Add skill
fastskill skill add https://github.com/user/new-skill.git

# 2. Reindex to include in search
fastskill index rebuild

# 3. Test discovery
fastskill skill search "skill name or description"
```

## Performance Considerations

### Reindexing

**File Hash Detection**:
- Files are hashed with SHA256 to detect changes
- Unchanged files are skipped during reindex
- Use `--force` to bypass hash cache

**Concurrency**:
- Reindex embeds skills **sequentially** (one at a time)
- `--max-concurrent` is accepted for compatibility but is currently a **no-op** — it does not change indexing speed or the number of concurrent API requests

### Searching

**Semantic Search**:
- Uses cosine similarity for ranking
- Embeddings are cached in SQLite database
- Search is O(log n) with vector index

**Query Tips**:
- Use natural language queries (similar to SKILL.md descriptions)
- Include relevant domain terms
- Try different query phrasings for better results

## Troubleshooting

<Accordions>
<Accordion id="search-returns-no-results" title="Search returns no results">
  <Callout type="warn">
  **Index not built**: Make sure you've run `fastskill index rebuild` after installing skills.
  </Callout>

  <Callout type="warn">
  **Query too specific**: Try broader terms or different phrasing.
  </Callout>

  <Callout type="warn">
  **Skills not installed**: Verify skills are in `.claude/skills/` with `fastskill skill list`.
  </Callout>
</Accordion>

<Accordion id="reindex-fails" title="Reindex fails">
  <Callout type="info">
  **OpenAI API key not set**: Set `OPENAI_API_KEY` environment variable.
  ```bash
  export OPENAI_API_KEY="your-key-here"
  fastskill index rebuild
  ```
  </Callout>

  <Callout type="info">
  **API rate limit errors**: Reindex already runs sequentially — wait and retry.
  </Callout>

  <Callout type="info">
  **Network errors**: Check internet connectivity and OpenAI API status.
  </Callout>
</Accordion>

<Accordion id="repository-not-found" title="Repository not found">
  <Callout>
  **Invalid repository name**: Check repository name with `fastskill repo list`.
  </Callout>

  <Callout>
  **Repository URL incorrect**: Verify URL is accessible with `fastskill repo test <name>`.
  </Callout>

  <Callout>
  **Authentication failed**: Verify authentication type and credentials with `fastskill repo info <name>`.
  </Callout>
</Accordion>
</Accordions>

## Best Practices

### 1. Reindex after changes

Always run `fastskill index rebuild` after installing, updating, or modifying skills to keep search index current.

### 2. Use natural language queries

Search queries work best with natural language that matches skill descriptions in SKILL.md files.

### 3. Organize repositories by priority

Set lower priority numbers for primary repositories to ensure preferred skills are discovered first.

### 4. Test repositories after configuration

Use `fastskill repo test <name>` to verify repositories are accessible before using them.

### 5. Reindex incrementally

Reindex skips unchanged skills by default (via the file-hash cache), so routine reindexing is cheap. Use `--force` only when you need to rebuild every embedding.
