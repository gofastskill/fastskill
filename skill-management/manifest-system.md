## Project configuration

A project's `skill-project.toml` defines the installation directory and desired
skills. FastSkill finds it by walking up from your working directory. Paths in the
manifest are relative to the manifest directory, not the calling shell's directory.

```toml
[dependencies]
review-notes = { origin = { type = "local", path = "./source/review-notes" } }

[tool.fastskill]
skills_directory = ".claude/skills"
```

Use the [quickstart](/quickstart) to create this local source. `skill add` writes a
dependency and installs it. Editing the manifest manually requires a subsequent
`project install` to apply it.

FastSkill refuses a manifest with a key it does not recognise under
`[tool.fastskill]`, so a misspelt setting fails loudly instead of being ignored.
Other tables, such as `[tool.<other-tool>]`, are left alone and kept on save.

## Manifest composition

Reference a reusable team Manifest without copying its dependencies:

```toml
[tool.fastskill.manifests]
platform = "../platform-team/skill-project.toml"
data = "../data-team"
```

A reference may name the file or its containing directory. References are recursive and their
paths are relative to the Manifest containing the declaration. Dependencies inside each referenced
Manifest keep their own path base, so a shared Manifest may combine Git, repository, ZIP URL, and
shared-filesystem origins normally.

`project install` resolves all composed roots into the consuming project's `skills.lock`. Repeated
identical declarations are deduplicated. Missing files, cycles, or different origins/groups for the
same skill ID are errors and stop installation before managed state changes.

Manifest composition is supported in author-controlled project manifests. Installed or fetched
skill packages must declare dependencies directly; their manifest references are rejected before
any referenced file is read. This prevents packages from importing host project files.

## Dependency origins

These are examples of source declarations, not publicly available packages:

```toml
[dependencies]
local-skill = { origin = { type = "local", path = "./source/local-skill" } }
editable-skill = { origin = { type = "local", path = "./source/editable-skill", editable = true }, groups = ["dev"] }
git-skill = { origin = { type = "git", url = "https://github.com/your-org/git-skill.git", ref = { branch = "main" } } }
zip-skill = { origin = { type = "zip-url", url = "https://example.com/zip-skill.zip" } }
catalog-skill = { origin = { type = "repository", repo = "team", skill = "catalog-skill", version = "1.0.0" } }
```

A repository origin refers to a configured catalog. See [source configuration](/registry/sources).
Use `skill add` to produce declarations from actual sources rather than guessing IDs.
Editable local dependencies link to their source and are intentionally mutable;
other local dependencies are copied and checked against locked integrity evidence.

## Groups

Groups select optional roots. Required transitive dependencies remain part of the
selected roots' installation closure.

```bash
fastskill project install --without dev
fastskill project install --only dev
```

Use one group selection mode per invocation. A group-limited lock may not cover
roots excluded from that resolution; `--lock` cannot resolve missing coverage.

## Locked restoration and updates

`skills.lock` records the resolved result of local and composed Manifest roots: origins, versions, Git commits, content digests,
dependency edges, groups, covered roots, bundle ownership, and overrides. It is
generated by FastSkill; do not hand-write a partial lockfile.

```bash
fastskill project install
fastskill project install --lock
fastskill skill update --dry-run
fastskill skill list --check
```

Ordinary installation reuses compatible locked selections and resolves roots that
lack coverage. `--lock` verifies and restores the recorded selection without
changing lock bytes. Updates deliberately resolve changes within the declared
constraints; exact pins stay pinned unless explicitly changed.

Commit the manifest and lock together. Local sources and cached bundle artifacts
must also be available to recipients. `--offline` prevents network access; it
requires all necessary verified inputs locally and does not make remote dependencies
portable by itself. See [bundle distribution](/cli-reference/bundle-command).

## Project and global scope

Project operations use the manifest's installation directory. `--skills-dir`
overrides that destination when supported. Global operations use the user-level
skill set and `global-skills.lock`; the default directory is
`~/.config/fastskill/skills` on Unix.

```bash
fastskill skill list --global
fastskill project install --global --lock
```

A global FastSkill directory is not automatically an agent's discovery directory.
Confirm the location your agent reads or access global skills through MCP.
Global lock restoration does not require a project manifest.

## Author configuration

Within a skill directory, `skill-project.toml` can also carry author metadata and
skill dependencies. A standalone skill can begin with only `SKILL.md`; separate
project configuration controls where consumers install it. See
[skill validation](/skill-management/validation) and [project init](/cli-reference/init-command).
